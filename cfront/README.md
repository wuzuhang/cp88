# 球序 H5

Vue 3 + Vite 的双色球分析前端，参考 `cp88/src/views/other.vue` 的出球位置统计方式，使用 Go 后端中的真实开奖记录。

## 启动

先从项目根目录启动后端 `go run .`，再在 `cfront` 中执行：

```sh
npm install
npm run dev
```

访问 `http://127.0.0.1:5173`。开发服务器将 `/api` 代理到 `http://127.0.0.1:8080`，无需另行设置 CORS。代理地址可在 `.env.local` 中设置 `API_PROXY_TARGET`。

## 页面与统计口径

- 频次矩阵：六列使用实际出球顺序 `seq_red_1`–`seq_red_6`。红、蓝球共用一个样本选择器，默认 100 期，可选 100–1000 期共十档，同步重算频次与遗漏。左列统计全部红球次数，各位置列分别按频次排序，相同行不是一组号码。
- 初始化是预测尚未开奖的下一期：500 期样本包含最新已开奖期，再取之前 499 期；频次与遗漏均使用这个样本，页面不显示下一期中奖号码。向前一步进入最新已开奖期的历史对照，显示该期真实中奖号码，样本从该期上一期起取 500 条；向后回到初始状态时恢复下一期预测。每次切换重算频次与遗漏，红球和蓝球共用所选样本期数。
- 矩阵显示各位置号码的频次与遗漏，不显示中奖号码频次合值。遗漏表示从目标期上一期向前连续未出现的期数，上一期同位置出现为 0；样本内未出现则标注 `≥实际样本期数`。福彩3D采用相同口径，按百、十、个位统计并保留 0 与重复数字。
- 更新开奖：手动抓取当前玩法数据源中的最新已开奖期并保存，成功后刷新数据；显示更新中和成功/失败提示。“刷新数据”仅重新读取已有开奖记录。
- 预测参考：双色球与福彩3D分别提供生成10注按钮，使用当前所选的实际样本和历史目标期。生成后显示样本范围、和值均值及标准差、平均跨度、位置平均信息熵。双色球10注按同一模型独立生成，注间允许重复号码乃至完整组合，每注内部红球不重复；3D保留10组去重的规则。可载入任意一注继续分析，切换样本/目标期或刷新数据会清除旧结果。
- 预测结果：双色球和3D均保留并显示全部10注，编号01～10，按原始生成顺序展示，每注均可载入并进行开奖命中比较。
- 双色球快捷预测：点击“向前一期并预测10注”，先将目标期向前切换一期，等待新目标期、样本和开奖结果传给预测组件后再生成10注；自动使用新目标期的真实开奖结果做命中对比。计算期间防止重复点击，到达当前已加载数据的完整样本边界时禁用按钮。原有单独切换和预测按钮保留。
- 开奖对照：历史目标期已有开奖结果时，参考号码列表用实心球和勾号标出命中，并显示每注的命中数量。双色球红球按集合比较、不要求出球位置相同，蓝球单独比较；3D按百、十、个位逐位比较，数字相同但位置不同不算同位命中。下一期未开奖时不显示命中状态。开奖结果只传给展示层的比较函数，不参与模型生成。
- 号码选择：最多六个不同红球和一个蓝球，支持按位置选择、直接选号、随机生成与清空。
- 组合分析：调用后端，显示红球和值、跨度、奇偶及三区比例。修改号码后清除旧结果。
- 开奖历史：初次分页加载最新 1500 期，覆盖最高 1000 期样本并预留历史对照范围；支持筛选已加载的期号/日期，加载更多可继续读取数据库中的早期记录。
- 手机底部保留选号进度、随机选号及分析按钮，支持安全区域；页面也适配平板与桌面。

统计描述历史分布，不推断中奖概率。

## 10注预测参考的计算方法

计算在浏览器中完成，不额外传输开奖记录。输入仅为当前窗口实际样本：下一期参考包含最新已开奖期；历史回看排除目标期和更新开奖。没有数据或号码非法时提示错误。

1. 每个出球位置建立分类频率模型，使用对称 Dirichlet 先验，总伪计数固定为 50。对有 K 个号码、N 期样本、号码出现 c 次的位置，后验均值为 `(c + 50/K) / (N + 50)`。这让未出现号码保留正权重，减少短期频率波动；50 是预设平滑参数，未宣称为最优参数。公式参见 [华盛顿大学分类/多项分布贝叶斯推导](https://faculty.washington.edu/yenchic/20A_stat512/Lec7_Multinomial.html)。
2. 用 `-sum(p*log(p))/log(K)` 描述位置分布的归一化信息熵，0–1 越大越均匀。这是分布描述，不是准确率。熵定义参见 [NIST](https://csrc.nist.gov/glossary/term/entropy)。和值均值、标准差和跨度也只描述历史样本，不用作硬性排除规则。
3. 双色球以六个出球位置分别统计当前样本的遗漏。每个位置排除遗漏最大和最小的全部并列号码；未出现号码统一以实际样本期数作为遗漏下界，作为样本内最大档一并处理。蓝球按蓝球列同样排除极值，并排除样本最新一期蓝球。上期红球指样本最新一期的六个红球：每注与它们恰好重合1～2个，其余上期红球不能再选；红球必须恰好只有一组差值为1的两连号，禁止三连号及以上，也禁止两组或更多互不相连的两连号。

   动态规划状态包括号码下标、未分配位置子集、已选上期红球数(0～2)、已选相邻对数（0～1）、上一个数字是否选中。每个号码最多分配给一个允许的位置，按同时满足全部条件的模型权重独立抽取六个红球，再从允许蓝球中按权重独立抽取蓝球。10注之间不去重、不改变权重、不施加分散惩罚。没有可用蓝球或红球条件无解时明确报错，不放宽筛选、不用补号凑数。

   页面提供上期参考期号、各位置排除名单、每注重号数、连号和位置参考；红球主体仍按升序显示。载入选号区时使用位置参考。历史回看只用目标期之前的样本，条件中的上期也从该样本取得，不能引用目标期真实开奖号。
4. 3D完整枚举000–999，以百、十、个位平滑权重的乘积作为独立位置模型权重。保留前导0、重复数字及豹子，输出按单选的有序三位号码解释。
5. 仅3D保留原有分散规则：在候选集合内按 `exp(log模型权重 - 2*与已选组合的最大相似度)` 不放回抽取10注，相似度为相同位置数/3。系数2是分散组合的启发式参数，不把分散抽样解释为提升中奖率。双色球不采用此规则。

位置独立是建模假设，不是证明出的真实开奖机制；输出不提供校准后的中奖概率，也未经过有效性回测。遗漏不用于推断号码“该出了”。公平独立开奖下，历史统计不会改变每个合法组合的理论中奖概率；这些号码仅供统计参考，序号不表示中奖率排名。

矩阵颜色按实际样本期数动态归一化。每列平均频次为实际期数除以号码数量（红球 33、蓝球 16）；浅至深五档分别表示不超过均值的 50%、85%、115%、150% 及高于 150%。同一出现比例在 100 期与 1000 期中使用相同颜色，切换历史窗口后也会重新计算。

## 接口

- `GET /api/v1/records?limit=500&offset=0`：返回 `items`、`total`、`limit`、`offset`，按日期和期号降序。
- `POST /api/v1/analysis`：传入 `red_balls` 和 `blue_ball`，返回组合特征。

## 检查与构建

```sh
npm test
npm run build
npm run preview
```

构建输出为 `cfront/dist`。根目录 Dockerfile 包含前后端构建阶段，执行 `docker compose up --build -d` 部署 Go 后端与 Nginx H5 前端。默认访问 `http://localhost`，Nginx 将 `/api` 转发到后端。数据库及端口配置见根目录 README。
